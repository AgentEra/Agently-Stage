# Stage 性能策略实验合同

日期：2026-10-22。研究阶段，非生产优化或发布。基线：`cfa1db5b9663b4559226dfab4db120adcac22b11`，Stage 0.3.8；分支 `feature/performance-strategy-evaluation`。

## 目标与判定

在保持所测契约的前提下筛选减少 CPU 成本、提高有效吞吐或降低尾延迟的策略。CPU 满载不是目标。所有负载均为**合成基础设施实验**，模型/API调用均为0，不代表LLM效果、真实网络或生产容量。实验候选仅位于本目录，不改生产包。

预声明：每个性能配置独立子进程，至少5次重复，固定随机种子打乱每轮配置顺序；先预热再计时，另记录冷进程总耗时。计算检查准确结果，通道检查数量/顺序，生命周期独立验证。保留所有有效重复，不按结果删异常值。失败/超时单列，不进入有效性能汇总。中位数、最小最大及逐轮配对差异不冒充置信区间。

保留规则：确定性正确性是硬门槛。候选在目标规模的5轮配对比较中至少4轮改善且中位改善≥10%，可保留为该场景候选；若只在某些规模成立则条件保留。内存或P99恶化需单独披露，不以吞吐抵销。门槛用于本轮筛选，不是统计显著性或生产SLA。不满足则淘汰该配置或证据不足，不扩大为否定整个技术。

## 测量与归因

记录wall time、进程CPU时间、CPU/wall、CPU/操作、操作吞吐、请求延迟分位、原始延迟数组、端点RSS（父子求和，非峰值）、上下文切换及冷启动总时间。子进程CPU在进程存活期间按预热后快照做差，不只统计父进程；结果序列/校验值同源核对。观察器只在计时边界采样，避免循环枚举污染延迟。运行标明GC设置、OS、核心、解释器、依赖、编译命令和源码哈希。

若发现runner或测量错误，保留诊断记录与排除原因，修正后整组重跑；不得混用前后数据。计时中不运行其他实验/构建，不主动终止用户其他服务；外部负载和异构核心影响仍是限制。所有执行带安全超时，超时仅算失败，不算性能结果。

## 资源与语义边界

本轮仅测试进程内Stage机制及显式计算边界。业务编排、持久恢复、外部副作用、模型语义、真实网络与生产Linux容量不在本实验覆盖。Go/Rust prototype没有替换Stage生命周期。候选通过不代表生产接受，仍需独立实现审查、完整兼容矩阵和Agently集成验收。
